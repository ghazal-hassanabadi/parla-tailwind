# Parla: بازطراحی با Tailwind (همراه با Dark Mode)

Parla یک سایت فروشگاهی اکسسوری است (RTL و mobile-first). نسخه‌ی اول را با HTML و CSS خام نوشته بودم. در این مرحله همان صفحه‌ها را با Tailwind v4 بازسازی کردم، با همان ظاهر، و بعد از آن **Dark Mode** را هم اضافه کردم تا تفاوت دو روش را در یک کار واقعی از نزدیک ببینم.



## هدف پروژه

- ساخت دوباره‌ی همان ظاهر نسخه‌ی CSS خام، فقط با کلاس‌های Tailwind
- تعریف رنگ‌های برند و فونت‌های فارسی یک بار در تنظیمات سفارشی
- افزودن Dark Mode بدون نوشتن دوباره‌ی استایل‌ها
- نوشتن مقایسه‌ی مکتوب: چه چیزی سریع‌تر شد، چه چیزی سخت‌تر، و حجم CSS چقدر تغییر کرد

## صفحه‌ها

- صفحه‌ی اصلی (header، hero، دسته‌بندی، تخفیف‌ها، محصولات، پلن‌ها، درباره‌ی ما، footer)
- صفحه‌ی تماس با ما
- صفحه‌ی ورود و ثبت نام

هر صفحه در سه اندازه‌ی mobile، tablet و desktop و در دو حالت روشن و تیره طراحی و آزمایش شده است.

## نسخه و اجرا

از Tailwind نسخه‌ی ۴ با CLI استفاده کرده‌ام. در این نسخه تنظیمات داخل فایل CSS ورودی و در بلاک `@theme` نوشته می‌شود، نه در یک فایل JavaScript جدا (مثل `tailwind.config.js` در نسخه‌های قبل).

نصب:

```
npm install
```

ساخت خودکار فایل خروجی (باید هنگام کار باز بماند):

```
npx @tailwindcss/cli -i ./src/input.css -o ./src/output.css --watch
```

ساخت minify شده برای اندازه‌گیری حجم نهایی:

```
npx @tailwindcss/cli -i ./src/input.css -o ./src/output.css --minify
```



## تنظیمات سفارشی (`@theme`)

در فایل `input.css` رنگ‌های برند، فونت‌ها و اندازه‌های font-size را یک بار تعریف کرده‌ام و در همه‌ی صفحه‌ها فقط اسمشان را صدا می‌زنم. نمونه‌ی ساختار:

```css
@import "tailwindcss";

@theme {
  --color-olive: ...;
  --font-lalezar: "Lalezar", system-ui;
  --font-vazir: "Vazirmatn", system-ui;
  --font-playfair: "Playfair Display", serif;
  --text-13: 13px;
}
```

رنگ‌ها:

```
olive, olive-light, olive-dark, olive-hover
taupe-dark, taupe-light, taupe-hover
mauve, welcome, tan, cream
hero-overlay, hero-btn-hover, figure-shadow
button, field-text, send-hover
```

فونت‌ها:

| فونت | کاربرد |
|---|---|
| Lalezar | متن‌های اصلی و تیترها |
| Vazirmatn | متن فارسی خوانا |
| Playfair Display | نام برند |

اندازه‌های font-size که در Tailwind آماده نبود (مثل ۱۰، ۱۳، ۱۵، ۱۷، ۱۹، ۲۱، ۲۸، ۳۲، ۳۶، ۴۰، ۴۴ و ۵۰ پیکسل) را هم در همین بلاک اسم‌گذاری کرده‌ام.

از arbitrary value با کروشه فقط جایی استفاده کرده‌ام که واقعاً لازم بود (درصدها و چند محاسبه). بقیه‌ی اندازه‌ها از scale خود Tailwind ساخته شده است (هر واحد چهار پیکسل).

## Dark Mode

### روش کار

در Tailwind v4 به‌طور پیش‌فرض `dark:` بر اساس تنظیم سیستم‌عامل (`prefers-color-scheme`) کار می‌کند. چون می‌خواستم کاربر با یک دکمه خودش حالت را عوض کند، `dark:` را به یک کلاس روی تگ `html` وصل کردم. در `input.css`:

```css
@custom-variant dark (&:where(.dark, .dark *));
```

بعد از این، هر کلاس با prefix `dark:` فقط وقتی اعمال می‌شود که `html` کلاس `dark` داشته باشد. مثال:

```html
<body class="bg-cream text-taupe-dark dark:bg-neutral-900 dark:text-neutral-100">
```

### دکمه‌ی تغییر حالت

- دکمه کلاس `dark` را روی `document.documentElement` اضافه یا حذف می‌کند.
- انتخاب کاربر در `localStorage` ذخیره می‌شود.
- اگر کاربر قبلاً چیزی انتخاب نکرده باشد، تنظیم سیستم‌عامل خوانده می‌شود.
- یک اسکریپت کوتاه داخل `<head>` (قبل از بارگذاری صفحه) کلاس را اعمال می‌کند تا هنگام باز شدن صفحه، لحظه‌ای حالت روشن دیده نشود (پرش رنگ).

### رنگ‌ها در حالت تیره

- رنگ‌های برند (olive، taupe، ...) در حالت تیره هم استفاده می‌شوند. فقط زمینه‌ها، رنگ متن‌ها و کارت‌ها عوض می‌شوند.
- زمینه‌ها و متن‌های تیره هم در `@theme` اسم گرفته‌اند تا مثل رنگ‌های برند فقط در یک جا تغییر کنند.
- خود رنگ‌های برند را روی زمینه‌ی تیره از نظر خوانایی (کنتراست) بررسی کردم. جایی که کنتراست کم بود، نسخه‌ی روشن‌تر همان رنگ (مثل `olive-light`) را برای `dark:` گذاشتم.


## مقایسه با نسخه‌ی CSS خام

### حجم

| | حجم |
|---|---|
| CSS خام صفحه‌ی اصلی | ۶۶٬۹۱۹ بایت |
| CSS خام صفحه‌ی تماس | ۱۶٬۳۱۷ بایت |
| CSS خام صفحه‌ی ثبت نام | ۸٬۳۴۲ بایت |
| جمع سه فایل خام | ۹۱٬۵۷۸ بایت (حدود ۸۹٫۴ کیلوبایت) |
| فایل `output.css` بعد از minify (قبل از Dark Mode) | ۳۳٬۷۰۰ بایت (حدود ۳۲٫۹ کیلوبایت) |
| فایل `output.css` بعد از minify (با Dark Mode) | ___ بایت |
| تغییر نسبت به CSS خام (قبل از Dark Mode) | ۵۷٬۸۷۸ بایت کمتر، حدود ۶۳٫۲ درصد کاهش |

توضیح‌ها:

- فایل‌های CSS خام minify نشده بودند و پر از فاصله و خط خالی بودند، پس مقایسه‌ی مستقیم کاملاً هم‌سطح نیست.
- Tailwind فقط کلاس‌هایی را در خروجی می‌گذارد که واقعاً در صفحه‌ها استفاده شده است. به همین دلیل خروجی کوچک می‌ماند.
- نسخه‌ی خام هیچ Dark Mode‌ای نداشت. اگر Dark Mode را با CSS خام می‌نوشتم باید بخش بزرگی از قانون‌ها را دوباره می‌نوشتم (یا متغیرهای CSS تعریف می‌کردم). در Tailwind هر کلاس `dark:` فقط چند بایت به خروجی اضافه می‌کند، و حجم جدید در ردیف بالا ثبت شده است.

### چه چیزی سریع‌تر شد

- دیگر بین فایل HTML و فایل CSS رفت‌وآمد نمی‌کنم. استایل همان جایی است که تگ نوشته می‌شود.
- اسم‌گذاری کلاس‌ها (مثل اسم برای هر تکه) حذف شد و کلی وقت آزاد کرد.
- کلاس‌های مخصوص هر اندازه‌ی صفحه با prefix (مثل `md:` و `xl:`) روی همان تگ نوشته می‌شوند و دیگر دنبال media queryها در انتهای فایل CSS نمی‌گردم.
- تغییر رنگ برند فقط در یک جا (`@theme`) انجام می‌شود.
- افزودن Dark Mode به‌جای نوشتن یک فایل CSS دوم، فقط اضافه کردن چند کلاس `dark:` کنار کلاس‌های موجود بود.
- حجم نهایی بدون هیچ تلاشی خودبه‌خود کوچک شد، چون کلاس‌های استفاده‌نشده در خروجی نمی‌آیند.

### چه چیزی سخت‌تر شد

- در ابتدا باید اسم کلاس‌ها و معادل CSS آن‌ها را بلد باشی. بدون دانستن CSS خام، این کار شانسی می‌شود.
- رشته‌ی کلاس‌ها در فایل HTML بلند و شلوغ شد، به‌خصوص با اضافه شدن prefixهای `md:`، `xl:` و `dark:` روی یک تگ.
- در دوره‌ی مهاجرت، قانون‌های قدیمی فایل CSS بر کلاس‌های Tailwind غلبه می‌کردند و اثرشان را از بین می‌بردند. هر بار باید قانون قدیمی همان بخش را پاک می‌کردم.
- Tailwind به‌طور پیش‌فرض (Preflight) اندازه‌ی heading‌ها، رنگ زمینه‌ی inputها و بسیاری چیزهای دیگر را reset می‌کند. چیزهایی که مرورگر خودش می‌داد (مثل ضخامت تیتر یا زمینه‌ی سفید input) باید دستی نوشته می‌شد.
- تبدیل اندازه‌های پیکسلی طرح قدیمی به scale خود Tailwind وقت می‌گرفت.
- کارت‌های محصول چند بار تکرار شده‌اند و فعلاً به شکل کپی ساختار هستند.
- Dark Mode فقط یک کلاس نیست: باید همه‌ی بخش‌ها را در حالت تیره دوباره آزمایش کنم (متن، سایه، input، overlay) و جاهای فراموش‌شده را پیدا کنم.
- در v4 تنظیم `dark:` برای کنترل با دکمه دیگر در فایل config نیست و باید با `@custom-variant` در CSS نوشته شود. این را اول نمی‌دانستم.

### جمع‌بندی مقایسه

| معیار | CSS خام | Tailwind |
|---|---|---|
| سرعت نوشتن استایل | کندتر (رفت‌وآمد بین فایل‌ها، اسم‌گذاری) | سریع‌تر |
| خوانایی HTML | تمیزتر | شلوغ‌تر |
| حجم CSS نهایی | ۹۱٬۵۷۸ بایت (سه فایل) | ۳۳٬۷۰۰ بایت (قبل از Dark Mode) |
| تغییر رنگ برند | چند جا | یک جا (`@theme`) |
| Dark Mode | نیاز به بازنویسی یا متغیرهای جدا | کلاس `dark:` کنار کلاس‌های موجود |
| منحنی یادگیری | ملایم | نیاز به دانستن CSS و اسم کلاس‌ها |

## نتیجه‌گیری

Tailwind سرعت کار روزمره را بالا می‌برد، حجم CSS نهایی را به‌طور محسوس کم می‌کند (حدود ۶۳ درصد در این پروژه) و کارهایی مثل تغییر رنگ برند یا افزودن Dark Mode را ساده می‌کند. در عوض HTML شلوغ‌تر می‌شود و برای استفاده‌ی درست باید CSS خام را از قبل بلد باشی. برای پروژه‌ای مثل Parla که بخش‌های تکراری و ظاهر یکدست دارد، به نظرم انتخاب مناسبی است. قدم بعدی من جدا کردن کارت‌های تکراری محصول به یک component (یا partial) است تا رشته‌های بلند کلاس فقط در یک جا نوشته شوند.
